# UNICA & FLOWERS — магазин в браузере и Telegram

Каталог, корзина, заявки, история и переписка работают в обычном браузере и в Telegram Mini App. Главный адрес — https://app8754275738.tgcloud.ai/. Статика размещена в Telegram Serverless, общая база новой версии и серверные операции — в Sites D1. Сохранены оригинальный логотип, фотографии, 10 сортов и оформление предыдущей версии.

В обычном браузере страница Telegram-хостинга обращается к общему серверу по HTTPS с ограниченным CORS и токенами устройства. Это не требует сторонних cookies, регистрации в Telegram или ChatGPT. В Mini App запросы идут через `siteBridge`: Telegram Serverless подтверждает личность и роли, после чего передаёт их серверу Sites по соединению с секретным ключом. Данные `initDataUnsafe`, query-параметры и введённые в браузере ID не выдают прав.

Новые заказы и переписка общие для обоих режимов. Telegram-покупатель получает постоянную историю своего подтверждённого аккаунта. Между разными устройствами и браузером/Telegram доступ к конкретному заказу восстанавливается личной ссылкой. Учётные записи обычного сайта входят по паролю; в Mini App владелец 5211227935 и администратор 1154273072 входят по прежним подтверждённым ролям.

Прежняя версия сохранена в Telegram по `/legacy/index.html`. Из нового Mini App она открывается ссылкой «Прежние заказы и каталог» в управлении или «Мои прежние заказы в Telegram» в истории. Ранее созданные ботом заказы остаются в его базе; автоматический перенос персональных данных не выполнялся. Карточки новых заказов и ответы доступны боту через защищённое серверное соединение; прежние заказы сохраняют свою базу.

## Покупателю

- Поиск по русскому и латинскому названию, фильтры высоты и наличия, сортировка, подробные карточки.
- Сравнение до трёх сортов с фотографиями, размерами, ценой и наличием.
- Корзина с количеством, имя, необязательный телефон, самовывоз / доставка / согласование, пожелания. Адрес обязателен для доставки.
- Заявки сохраняются в серверной базе. Повторная отправка той же заявки не создаёт дубликат, даже после тайм-аута. Цены и наличие проверяются сервером.
- «Мои заказы»: статусы, история, отмена новой заявки, повтор выбора с актуальными условиями, переписка с магазином.
- Личный код и ссылка открывают заказ с другого устройства. Коды случайные, в базе хранится только хеш. Номер заказа сам по себе не даёт доступ. Ссылки используют URL fragment, который не передаётся серверу при открытии страницы, и удаляются из адресной строки после чтения.
- Памятка заказа скачивается в TXT. Личная ссылка сохраняется на устройстве, из истории можно создать новую, если старая потеряна.
- Имя и контакты запоминаются только с согласия пользователя. Для истории нужна cookie устройства или личный код. Без обоих способов анонимный заказ нельзя самостоятельно восстановить; свяжитесь с продавцом.

Все цены исходного каталога оставлены «по запросу». Если ни одна цена не известна, сайт пишет «Стоимость уточнит продавец». При смешанной корзине показывает известную часть суммы. Автоматической оплаты, расчёта доставки и резервирования фактических остатков нет: условия подтверждает магазин.

## Команде

Вход через кнопку «Вход для команды». Панель включает обзор, активные заказы, архив, товары с загрузкой фотографий, цены и наличие, настройки, журнал, CSV-экспорт и команду. Выполненные и отменённые заказы исчезают из активных и счётчика. Поиск работает по номеру, имени из формы (в том числе русскому без учёта регистра), телефону, адресу и пожеланиям.

Сотрудники отвечают покупателям непосредственно в переписке заказа. Переписка обновляется каждые 15 секунд, пока открыта. Уведомления о новых заявках, сообщениях и изменении статуса поступают администраторам в Telegram-бота. Статусы и ответы также доступны на сайте.

Владелец создаёт сотрудников, отзывает и возвращает доступ, меняет их пароли. Отзыв доступа и смена пароля завершают старые сеансы. Сотрудник не может управлять командой. Все серверные действия проверяют права. Пароли защищены PBKDF2-SHA-256 с индивидуальной солью; срок сеанса 8 часов. На собственном домене поддерживаются HttpOnly/SameSite cookies (Secure на HTTPS); для Telegram-домена, где сторонние cookies ненадёжны, парольный сеанс хранится в sessionStorage и передаётся отдельным HTTPS-заголовком. Токен истории устройства хранится отдельно. Владелец не может отключить свой аккаунт. Общих паролей или входа по query-параметру нет.

### Первый вход на Sites

Покупателям открыт публичный доступ по явному разрешению владельца. Покупки не требуют входа. Чтобы создать первый парольный аккаунт владельца, откройте Mini App владельцем и в управлении нажмите «Настроить вход из браузера». Второй способ: откройте Sites под подтверждённым ChatGPT аккаунтом владельца и нажмите «Настроить магазин». Создайте логин, имя и пароль от 12 символов. Затем добавьте маму во вкладке «Команда». Telegram-администратор уже может управлять магазином без парольного аккаунта; создать первого парольного владельца может только владелец.

Новая база общая для браузера и Mini App; бот читает её через серверное соединение. Уведомления приходят в Telegram, ответы продавца и изменения статуса сохраняются на сайте.

## Запуск на компьютере

Требуется Node.js 22.15+.

```powershell
node scripts/local-server.mjs
```

Откройте http://localhost:4180/ (для встроенного браузера используйте localhost). Это полноценный локальный сервер с SQLite, без npm-зависимостей. База: `.local/shop.sqlite`; первый локальный аккаунт `owner` получает случайный пароль, сохранённый только в `.local/access.txt`. Эти файлы игнорируются Git, не публикуются и не попадают в архив Sites. Локальная и облачная базы отдельны. Пока локальный сервер остановлен, локальный сайт недоступен. Привязка по умолчанию только к loopback.

Скопировать согласованный снимок локальной базы, включая текущую WAL-историю:

```powershell
node scripts/backup-local.mjs
```

Результат: `.local/backups/*.sqlite`. Для восстановления остановите локальный сервер и восстановите снимок в отдельной чистой `.local/` под именем `shop.sqlite`; не подменяйте открытую базу и не смешивайте её с оставшимися `-wal`/`-shm`.

## Проверка и публикация

```powershell
node --test scripts/shop.test.mjs
npm run db:generate
npm run build
```

Общая серверная логика: `server/shop.mjs`. Она использует интерфейс D1, локальный адаптер — `server/sqlite.mjs`. Тесты исполняют реальную логику с SQLite в памяти; данные не отправляются покупателям. Hosted route: `app/api/[action]/route.ts`, рабочая база — Sites D1 binding `DB`. Схема и версионируемые SQL-миграции — `db/` и `drizzle/`. Выполнять CREATE/ALTER таблиц в обработчиках не требуется.

Публикация: сначала Sites с binding `DB` и секретом окружения `TELEGRAM_BRIDGE_SECRET`, затем конфигурация `site-bridge` в таблице settings Telegram, затем файлы `public/` копируются в `UNIKAFLOWERS_V2/web/` и выполняется `tgcloud push`. Не заменяйте существующий серверный ключ без согласованного обновления обеих сторон. `scripts/configure-site-bridge.mjs` в Telegram-проекте принимает ключ только по скрытому stdin; секрет не входит в исходники и frontend.

Серверные тесты сайта: 25 сценариев. Тесты Telegram-проекта: 34 сценария, включая границу доверия siteBridge. Изолированная UI-проверка: `node scripts/dual-qa.mjs`, http://localhost:4183/ — браузер, http://localhost:4183/?telegram — имитация SDK и ролей только на локальном стенде. База в памяти, после остановки тестовые данные исчезают. Скрипт не публикуется в статику.

Резервная копия перед работой: `D:\.Progi\codex\backups\UNICA-before-standalone-20261020`. Включает исходные файлы V2 и старый статический сайт; `.tgcloud`, `.git`, node_modules исключены. Облачная база Telegram не изменялась.
