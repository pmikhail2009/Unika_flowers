# UNICA & FLOWERS · магазин и Telegram-бот

Магазин гортензий на Telegram Serverless: каталог, корзина, заявки, история покупателя и панель команды. Код бота — в `tgcloud/`, сайт — в `web/`. Установка отдельного сервера и Bot API token не требуются.

- Бот: [@Unika_Flowers_bot](https://t.me/Unika_Flowers_bot)
- Mini App: https://app8754275738.tgcloud.ai/
- Продавец: [@unika_flowers](https://t.me/unika_flowers)

## Покупателю

Откройте магазин через бота. Поиск, фильтры по размеру и наличию, сортировка по цене и характеристикам помогают выбрать сорт. В карточке видны фотография, описание, цена и доступность: «В наличии», «Предзаказ» или «Нет в наличии».

В «Моём выборе» задайте количество, имя и получение. Телефон необязателен. Для доставки нужен город / адрес для согласования. Список и пожелания сохраняются на устройстве; контакты сохраняются только при включённой галочке. Корзина очищается после успешного сохранения заявки. Повторное нажатие и повтор после задержки ответа используют тот же номер запроса и не создают второй заказ.

«Мои заказы» показывает все заявки покупателя с постраничной навигацией, позициями, суммой и историей статусов. Новую заявку можно отменить до подтверждения; выбор из прежнего заказа можно повторить с актуальными ценами и наличием. У администратора на главном экране вместо этой кнопки отображается «Заказы (количество)» — общая история всех покупателей, включая отменённые и завершённые заявки.

## Переписка и уведомления

Покупатель может написать текст, отправить фото, файл или голосовое в личный чат бота. Кнопка «Написать магазину» и `/support` открывают этот сценарий явно. Сообщения поступают обоим администраторам; полный маршрут хранится по паре Telegram chat ID / message ID.

Администратор отвечает функцией Telegram **«Ответить»** на уведомление заказа или сообщение покупателя, либо нажимает **«Ответить через бота»** в карточке заказа. Бот предлагает ответить на конкретный запрос. Покупатель получает скопированное сообщение **от бота магазина**, без ссылки на личный аккаунт администратора. Следующий ответ покупателя вновь поступает команде. Сообщение администратора без адресата не пересылается покупателю автоматически. Для просмотра обращений есть **«Диалоги»** и `/inbox`, в том числе при сбое доставки уведомления. Из админки сайта кнопка ответа открывает нужный заказ в боте.

Уведомления о заказах записываются отдельно для каждого администратора: очередь доставки, попытки, ошибка Telegram и прочтение. Прочтение одним администратором не скрывает запись у второго. Недоставленные уведомления повторяются при `/start` администратора и по кнопке повтора под списком; интервал между попытками одного уведомления — 30 секунд. Фоновый планировщик для повторов не настроен. В старые записи очередь достраивается без удаления истории.

Иконки сайта — локальные SVG, одинаковые на ПК и телефоне. Большая декоративная звезда удалена. Файлы интерфейса имеют версию URL, чтобы Telegram не показывал старые значки из кэша.

Заявка требует подтверждения продавца. Автоматической оплаты, гарантированного бронирования остатков и тарификации доставки нет: эти условия согласуются с магазином. Если у товара нет цены, показывается известная часть суммы, а не вымышленный итог.

В обычном браузере доступна ознакомительная коллекция из JSON, с явной пометкой. Актуальная база, сохранение заказов и панель команды доступны при подтверждённой Telegram-авторизации. Кнопка оформления во внешнем браузере открывает магазин через бота; текст выбранных позиций также можно скопировать. Переписка с магазином открывается через бота.

## Команде

Роли привязаны к числовым Telegram ID в `tgcloud/lib/config.js`:

- **Владелец — 5211227935.** Управляет магазином и доступом команды.
- **Закреплённый администратор — 1154273072.** Управляет товарами, заказами и настройками.

Дополнительных администраторов владелец добавляет и удаляет на вкладке «Команда». Закреплённые ID меняются только в конфигурации проекта. Ни сообщения, ни пароли, ни query-параметры URL не выдают права. У каждого серверного действия есть проверка роли; история заказов всегда ограничена текущим покупателем.

Оба администратора должны один раз открыть бота и нажать **Start**, чтобы Telegram разрешил доставлять уведомления. Затем выполните **/admin** или откройте магазин и нажмите **«Управление»**.

В панели доступны:

- Обзор новых заявок, заказов в работе, ассортимента и покупателей.
- Заказы: поиск по номеру, имени, Telegram ID и пожеланиям, фильтр статуса, контакт покупателя, отметка прочтения, история, постраничный список и CSV-экспорт текущей выборки.
- Товары: создание и редактирование названия, описаний, размеров, цены, доступности и фото; скрытие и восстановление без удаления истории. Загрузчик уменьшает фото перед отправкой. Экспорт каталога в CSV.
- Настройки: пауза приёма новых заявок, объявление над каталогом, получение и оплата.
- Журнал: кто и когда изменил товары, цены, настройки, роли и статусы заказов.
- Команда: выдача и отзыв дополнительных ролей, только для владельца.

Статусы: **Новый → Подтверждён → Собирается → Готов к получению → Завершён**. В карточках и уведомлениях доступны явные кнопки «Принять заказ», «Завершить заказ», «Отменить заказ». Принятый заказ можно завершить сразу, минуя сборку и выдачу. Отменённый можно вернуть кнопкой «Принять заново»; история отмены сохраняется. Завершённый заказ остаётся в архиве без повторных действий. Покупатель получает уведомление о смене статуса. Проверка версии защищает от перезаписи изменений другим администратором; устаревшая кнопка в боте показывает актуальную карточку.

В боте также доступны добавление сорта по шагам, смена цены, скрытие / восстановление и управление заказами. Полный редактор находится в Mini App.

## Локальный запуск и проверка

Нужен **Node.js 22.15 или новее** (SQLite и VM используются только тестами). Серверный код работает в изолированном V8 Telegram, без npm-зависимостей.

```powershell
npm ci
npm run check
npm run dev
```

Сайт: http://127.0.0.1:4173/. Другой порт: `$env:PORT='4174'; npm run dev`.

Тесты исполняют настоящие обработчики с SQLite, подменяя только SDK и отправку Telegram-сообщений. Проверяются доступ, изоляция заказов, повторные запросы, цены, доступность, отмена, переходы статусов, конкурирующие изменения, роли и пауза.

Изолированный интерфейс для ручной проверки:

```powershell
node --experimental-vm-modules scripts/qa-server.mjs
```

Откройте http://127.0.0.1:4175/?role=owner (также `role=admin` и `role=buyer`). Это временная база в памяти, фотографии настоящие, цены и заказы тестовые, сообщения никуда не отправляются. Скрипт не входит в публикуемую папку `web/`; в рабочем сайте нет тестовой авторизации. После перезапуска стенда данные исчезают.

## Развёртывание

Для текущего магазина CLI уже авторизован в игнорируемой `.tgcloud/`. Не печатайте и не публикуйте её содержимое.

```powershell
npm run check
npx tgcloud migrate --local --dry-run
npx tgcloud migrate --local --safe
npm run deploy
npx tgcloud migrate --dry-run
npx tgcloud webhook
```

`node scripts/configure-bot.mjs` обновляет описание, меню и список команд, включая `/admin` для закреплённых аккаунтов. `node scripts/verify-cloud.mjs` сверяет серверные исходники и файлы сайта с облаком, проверяет роли, отказ неавторизованному API, схему и webhook; результат сохраняется в `verification.json`.

Сначала расширяется база, затем публикуются совместимые обработчики и сайт. Используйте только безопасные добавления. Уникальность номера запроса задаётся отдельным индексом, чтобы существующая SQLite-таблица расширялась без пересоздания. `push` сам не применяет миграции. Не используйте `--force` для обхода чужих обновлений.

Для другого бота нужны `npx tgcloud login`, его собственные ID команды, адрес в `APP_URL`, а также настройка Main App / Menu Button в @BotFather. Документация SDK находится в `node_modules/@tgcloud/cli/src/templates/docs/tgcloud-sdk.md`.

Для отката к исходному коду используйте **отдельную чистую папку** из `UNIKAFLOWERS_V2` в копии: `npm ci`, затем `npx tgcloud fetch` (обновляет снимок CLI, не файлы), `npx tgcloud push`. Дополнительные поля базы совместимы со старым кодом; удалять их не нужно. Старый код содержит выдачу админства по текстовой фразе, поэтому полный откат возвращает эту уязвимость. Восстановление данных из JSON выполняйте отдельно после свежей копии текущей базы и проверки изменений; не затирайте новые заказы старым снимком.
